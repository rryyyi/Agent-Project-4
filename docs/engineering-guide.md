# Agent 工程能力与演示路线

这个项目的展示价值来自可运行代码与可核对的工程决策。面试时建议从业务问题、控制边界和验证证据出发，准确区分已经交付的能力与后续规划。

## 能力映射

| 能力 | 实际实现 | 建议展示 |
| --- | --- | --- |
| 任务拆解 | Persona / Context / Provider / Guard / Environment / Evaluation | 从 `run_experiment` 解释数据如何流动 |
| Persona Design | 版本化 JSON、数值边界、证据字段、外部注册表 | 改动 cooperation 后复现实验，说明这是参数敏感性而非真人预测 |
| Prompt Engineering | system 契约 + JSON user 数据、简短解释与参数引用 | `prompts.py` 与真实调用轨迹 |
| 异步 Agent Harness | Semaphore、有界历史、轮次屏障、有限重试、预算 | 注入无效 JSON，查看 retries 和 valid_attempt_rate |
| 多 Agent 协作 | 同时公共物品行动；两阶段信任配对 | 解释同轮信息泄漏为何会改变实验 |
| 可靠性 | 超时、429/5xx 分类、认证快速失败、禁止隐式替换 Provider | 单测与 failed run 的原始 attempts |
| 结构化数据工程 | Pydantic、JSON Schema、配置快照、文本证据位置 | 从配置到结果的 JSON 契约 |
| 可观测性 | 每次调用上下文、校验结果、Token、耗时与来源 | 导出 JSON 后定位一次失败 |
| 实验评测 | 匹配种子、独立分支历史、配对单元、描述性指标 | 对比相同 offer 与不同 offer，解释统计边界 |
| 全栈交付 | FastAPI、CLI、响应式控制台、SQLite、Docker、CI | 现场完成一次运行与报告下载 |

## 五分钟演示

1. 启动 `personalab serve`，说明 Offline 是可复现教学基线。
2. 运行公共物品博弈，展示不同合作参数、动作和环境收益。
3. 打开轨迹，指出每个 Agent 只看到先前已结算轮次。
4. 运行 A/B，展示配对种子、合成群体差值与区间限制。
5. 下载 JSON 和 Markdown；指出模型标识、配置摘要、人格快照和失败分类。
6. 展示 `test_engine.py` 的非法输出、预算耗尽、超时和供应商适配测试。
7. 如果配置了真实服务，再用小规模 `examples/llm.json` 展示真实模型调用；否则清楚说明未执行真实模型基准。

## 可以深入讨论的工程问题

- 为什么收益计算必须放在环境层？模型对收益的自报告无法保证守恒或合法性。
- 为什么并发不等于把所有回合一起发出去？回合间有因果依赖，轮内才可以并发。
- 为什么 retries 需要和正常调用共用预算？否则错误会绕过成本上限。
- 为什么失败回合不自动补上默认动作？补值会悄悄改变实验方法；应保留未结算动作与失败原因。
- 为什么同种子对真实 LLM 不足以保证复现？模型版本、服务端调度和供应商实现都可能影响输出。
- 为什么 token usage 不是货币成本？模型价格、缓存收费与供应商计费语义不同。
- 为什么不直接使用更大的 Agent 框架？此范围内显式控制流更易审计；真实工具链或长任务复杂后再依据需要引入。
- 怎么升级为生产平台？先加入持久任务状态、Checkpoint、认证、租户配额与审计；现有 SQLite 终态快照不等于恢复机制。

## 与简历经历对应的表述

可依据当前实现使用以下描述，并按你真实完成和理解的部分调整：

> 设计并实现 PersonaLab 行为模拟实验平台，使用版本化 JSON 将人格特征、社会偏好与风险倾向建模为可校验参数，支持公共物品、两阶段信任与产品策略 A/B 三类模拟环境。
>
> 实现异步 Agent Harness，提供有界历史、轮次屏障、输出/动作校验、超时重试与调用预算；封装 OpenAI 兼容接口和可复现离线基线，记录逐次调用上下文、Token 与失败分类。
>
> 构建配对种子实验、描述性评测、SQLite 运行存储及 JSON/Markdown 自动报告，交付 FastAPI、CLI、交互控制台与 CI；文献证据抽取保留原文位置与文本摘要，便于核对。

上述描述不包含虚构的模型准确率、上线规模或业务收益。只有你自己能够解释、运行并维护这些代码时，它们才能在技术面试中成为可靠证据。仓库当前公开构建日期与提交历史按实际日期记录。
