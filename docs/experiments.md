# Experiment methods and reproducibility

## What the experiment measures

The system measures behavior generated by configured synthetic policies or a specified LLM under a known prompt and environment. It does not establish that these agents represent actual people. All four example personas are hand-authored; they contain no fabricated empirical evidence. The word “persona” describes a configuration contract, not a psychological diagnosis.

## Public goods

For n agents, each starts with 10 and chooses contribution c_i in [0,10]. The environment computes:

`payoff_i = 10 - c_i + 1.6 * sum(c) / n`.

For two contributions [0,10], payoffs are [18,8]. For four all contributing 10, every payoff is 16; for four all contributing 0, every payoff is 10. The default four-player setting has the usual tension between individual marginal return and group return. A one-player run is not that social dilemma.

Offline first-round contribution uses cooperation plus uniform seeded noise in [-0.08,0.08], scaled to [0,10]. With history it blends prior group mean contribution into the cooperation parameter using weight `0.35 * reciprocity`. This formula is an explicit teaching assumption. A high measured alignment score is expected by construction and does not validate personality science.

## Trust game

Each agent is an investor once per round and the next cyclic agent is its trustee. Investor chooses t in [0,10]. Trustee observes `received = 3t` and chooses fraction f in [0,1]. The environment pays:

- Investor: `10 - t + 3tf`.
- Trustee: `3t * (1-f)`.

For t=4 and f=0.5, payoffs are investor 12, trustee 6. There is no separate trustee initial endowment in this simplified version. Each trace has role and pair_id; do not compare a trustee fraction with an investor transfer as equal units. A one-person registry is explicitly self-play.

Offline investor base propensity is `0.5*cooperation + 0.4*risk_tolerance - 0.2*loss_aversion`, plus bounded seeded noise. Offline trustee fraction uses `0.45*reciprocity + 0.3*fairness`, plus noise, clamped to [0,1]. Repeated trust history is passed to real models, while this offline trust baseline only uses current parameters. This deliberately limits claims about emergent offline learning.

## Matched product A/B

Each A/B branch uses the same personas, root seed, repetition count and round count. Each agent sees only that branch's offer and history. A branch's previous-round group outcomes can affect real models, so this is a social simulation, not a claim of individually isolated real-user responses.

Offline choice uses a transparent logistic score from openness, risk tolerance, loss aversion and whether the text contains fixed privacy/transparency/trial keywords. It does not semantically understand offers. Matching the per-unit random draw reduces Monte Carlo noise; identical offers produce identical offline actions.

Statistical unit is `(persona_id, repetition)`. Average rounds inside each variant/unit. For matched units with equal completed round counts, define `d_j = mean(B_j) - mean(A_j)`. Report:

- Δ = mean(d).
- Approximate 95% interval = `Δ ± 1.96 * sample_std(d) / sqrt(number_of_pairs)`.

There is no interval for fewer than two matched units. This normal approximation can be poor for small samples and is not an exact binomial interval or population causal estimate. Repeated seed replicas of a few personas do not create a representative population. Interaction and shared prompts also limit independence. A failed run may contain partial matched units; inspect status and completed rounds.

## Metrics

- `legal_decision_rate`: settled valid decisions divided by planned decisions; failed partial-round valid candidates are intentionally not counted as settled.
- `valid_attempt_rate`: schema/action-valid provider calls divided by all actual calls; a retry is a new call.
- `cooperation_alignment_proxy`: mean of `1-abs(action/10-cooperation)` for public goods only.
- `by_persona`: descriptive means, not a statistical test of personality effects.
- `action_distribution`: exact action-value counts; continuous values are not binned.
- `input_tokens` and `output_tokens`: sum reported usage, including outputs that subsequently fail validation; missing usage becomes zero. Offline usage is zero.
- `elapsed_ms`: actual wall time, outside deterministic metrics. No claim of production throughput or monetary cost.

## Reproduce examples

```bash
python -m pip install -e ".[dev]"
python scripts/reproduce.py
```

Configurations live directly in `examples/*.json`; committed expected results in `examples/results/*.summary.json` include effective config, persona snapshots, decisions and deterministic metrics. Reports were generated by actual offline runs, not hand-written numbers. Full generated traces are placed in ignored `artifacts/reproduction/` to avoid making the repository unnecessarily large.

The script compares normalized outputs while excluding IDs, timestamps and timing. SHA-256 config hashes are included in the generated full runs and Markdown reports. If a justified policy/version change alters expected results, run `python scripts/reproduce.py --update`, inspect diffs and document the change.

Real LLM reproduction needs an account, supported endpoint, model version, environment configuration and model-specific investigation of repeatability. No real-model benchmark is shipped in this release.

## Source evidence workflow

1. Read a local TXT/Markdown/PDF with `read_document`.
2. Extract bounded keyword-matching sentence candidates.
3. Check exact Unicode offsets, extracted-text SHA-256 and PDF page anchor.
4. Human reviewer reads surrounding source and distinguishes an actual finding from a hypothesis.
5. Manually update persona evidence/parameters with rationale. Numeric values remain assumptions unless supported by a justified calibration procedure.

This workflow implements verifiable source extraction. It does not claim to automate scientific interpretation or infer Big Five scores from arbitrary text.

## Research references

The project borrows problem framing from Park et al. (2023), generative agents; Aher et al. (2023), LLM simulations of human subjects; and Berg et al. (1995), trust and reciprocity. See README links. The implementation is not a replication of their empirical findings. Future validation should pre-register hypotheses, use held-out human reference data, compare prompt/persona ablations, evaluate calibration and model sensitivity, and report failures alongside aggregate effects.
